Owner Maintenance Checklist

This page is for quick updates to your portfolio. If you need deeper code architecture notes, use the technical developer guide instead.

What to Update Most Often

  • Bio and intro — edit index.html
  • Project cards — edit js/projects-data.js
  • Resume details — edit js/resume-data.js
  • Images and screenshots — replace files in assets/images/ or assets/figma img/
Fast workflow: open the file, make the change, save it, and refresh the browser. No build step is required.

Recommended Preview Flow

  1. Open the site in VS Code
  2. Use a local preview or Live Server
  3. Save the updated file
  4. Refresh to confirm the change
Tip: Keep the Developer Guide for the technical file map. This page is meant to help you make content changes confidently.

Before You Publish

  • Check all links and project URLs
  • Verify the hero text and call-to-action buttons still read well
  • Confirm the portfolio looks clean on mobile
  • Make sure images are compressed and not stretched

Daily Update Pattern

One-Sentence Rule

When in doubt, start with the page copy and data file first. The developer guide exists for more technical troubleshooting, but most maintenance work stays simple and visual.

Add a Project

The fastest way: copy a template, fill in your info, save a screenshot, and refresh.

Step-by-Step

  1. Take a screenshot of your project (800×450px, 16:9 ratio)
  2. Save it to assets/images/ (e.g. my-project.png)
  3. Open js/projects-data.js
  4. Copy the template below
  5. Paste it before the closing ];
  6. Fill in your details
  7. Add a comma after the previous project if you're inserting in the middle
  8. Save and refresh
  9. The project will automatically appear on resume.html
Pro Tip: Number your projects with "01", "02", etc. This keeps them in order on the projects page.

Project Template

Copy this, paste it into the projects array, and replace the placeholder values:

{
  id: "my-project",
  number: "07",
  title: "My Project",
  summary: "One sentence about what it does and who it helps.",
  category: "interactive",
  image: "assets/images/my-project.png",
  tech: ["HTML", "CSS", "JavaScript"],
  liveUrl: "#",
  githubUrl: "https://github.com/yourusername/your-repo",
  details: [
    {
       heading: "<i class="fa-solid fa-bullseye"></i> The Real Problem",
      list: [
        "Feature One: What it does and why it matters.",
        "Feature Two: How it helps the user.",
        "Feature Three: What makes it stand out."
      ]
    },
    {
       heading: "<i class="fa-solid fa-rocket"></i> What I Learned",
      content: "<p>Your biggest takeaway from this project.</p>"
    }
  ]
}

Categories

Pick one of these for the category field:

  • educational — learning platforms, tutorials
  • corporate — business websites
  • design-system — UI kits, component libraries
  • interactive — apps, tools, games
  • form-design — forms, signup pages

Details Formats

Each section in details can be either:

  • Paragraphs: use content with HTML tags like <p> and <strong>
  • Bullet points: use list — the system auto-bolds text before the first colon

Mix both formats in the same project — no rules, just use what fits.

Update Content

Change text, skills, images, and links in the right place.

Edit Text

Most of the site text lives in index.html. Open it, find the section you want to change, and edit the text directly.

About Me is in the #about section (around line 135).

Education is in the #education section (around line 158).

My Approach is in the #approach section (around line 225).

For projects, edit the summary and details fields in js/projects-data.js.

Update Skills

Home page skills: in index.html inside the skills-section. Look for <span class="skill-tag"> and add, remove, or rename skills.

For the "Currently Exploring" section, wrap skills in <div class="skills-tags learning">.

Resume skills: edit js/resume-data.js — changes there update the resume page automatically.

Change Images

Profile photo: Replace the src in the About section of index.html.

Project screenshots: Save the new image to assets/images/, then update the image field in js/projects-data.js.

Tip: keep images under 200KB and use descriptive filenames like my-project-screenshot.png.

Update Links

Social links: in the Contact section of index.html.

Project links (live demo, GitHub): in js/projects-data.js.

Navigation links: in the <nav> at the top of index.html and projects.html.

Add or Update a Figma Design

The "Figma Designs" grid on the homepage works exactly like the projects grid: save a screenshot, add an entry to a data file, refresh.

  1. Save the screenshot to assets/figma img/
  2. Open js/figma-designs.js and copy an existing entry
  3. Update title and image
  4. Set liveUrl to the design's Figma prototype link, not the file link
Keep visitors view-only: in Figma, open the prototype and use the "Share prototype" button (not the regular Share button) to copy a link like figma.com/proto/.... Keep the permission dropdown on "can view" — that already blocks editing. For extra protection against people duplicating or exporting the file, go to Share → Advanced and turn off "Viewers can copy, share, and export from this file" (requires a paid Figma plan).

Resume System

How the auto-generated resume works and how to keep it in sync.

How the Resume Auto-Updates

The resume is built dynamically from two data sources:

  • js/resume-data.js — contains your name, title, contact info, professional summary, skills (technical, learning, soft), and education history.
  • js/projects-data.js — contains all your projects. The resume renderer automatically pulls every project from this file and adds it to the "Selected Projects" section.

When you add a new project to projects-data.js, it will appear on the resume the next time you load resume.html. No need to edit the resume manually.

Edit Resume Data

Open js/resume-data.js to update:

  • Personal info — name, title, email, location, summary
  • Skills — technical skills, learning skills, soft skills (each with icons)
  • Education — degrees, certifications, institutions

Each skill has an icon field using Font Awesome classes like fa-brands fa-html5.

Resume Display Rules

The resume renderer follows these rules:

  • Shows projects from resume-data.js first
  • Merges any NEW projects from projects-data.js (skips duplicates by title)
  • Hides "Live Demo" link if the URL is #
  • Groups tech tags under each project

If no projects are found, a helpful message appears telling you where to add them.

Change Styles

Tweak colors, fonts, spacing, and layout. All design tokens are in one place at the top of the CSS file.

Color Palette

Open css/style.css and look at the :root block at the top. Change any value to update the theme.

Accent #6ee7b7
Text #edf2f0
Background #060a08
Card #101a16
Quick Change: Changing --accent will update buttons, links, tags, and focus states everywhere. For a dark green theme use #34d399, for a blue theme use #60a5fa.

Fonts

The site uses Inter loaded from Google Fonts. To change it:

  1. Find the <link> tags in the <head> of index.html
  2. Replace with your font (Google Fonts, or a local @font-face)
  3. Update the font-family in css/style.css under body

Spacing & Layout

Section padding uses clamp() for responsive spacing. To make sections taller or shorter:

.section, .skills-section {
  padding: clamp(4.5rem, 8vw, 7rem) 0;
}

Grid layouts are defined with grid-template-columns. Change repeat(3, ...) to repeat(2, ...) to show fewer columns.

Add a New Section

  1. Add a <section> in index.html with a unique id
  2. Add a matching link in the navigation <nav>
  3. Style it in css/style.css
Tip: Use the existing sections as a template — they all follow the same pattern: <section> → .container → .section-title → content.

Deploy

Get your portfolio online in minutes. No build step needed.

Netlify

  1. Drag the portfolio folder onto app.netlify.com/drop
  2. Or connect your GitHub repo for auto-deploys
  3. Build command: leave empty
  4. Publish folder: /

Vercel

  1. Import your GitHub repo on vercel.com
  2. Framework: Other
  3. Build command: leave empty
  4. Output folder: /

GitHub Pages

  1. Push your code to a repo named username.github.io
  2. Go to Settings → Pages → Source: Deploy from branch
  3. Select main branch and / folder
  4. Your site will be live at https://username.github.io

Before You Deploy

Run through this checklist before going live:

  • Test all links and navigation
  • Check that images load
  • Verify the contact form works
  • Preview on mobile
  • Update the copyright year if needed
  • Make sure your email in the contact form is correct
Tip: Open the site in an incognito window to test it like a first-time visitor. This catches issues with cached assets or login-specific content.

Troubleshooting

Common issues and quick fixes.

Project not showing up

Check that:

  • You added a comma after the previous project object
  • The id is unique (no duplicates)
  • The image path is correct
  • You saved the file before refreshing
Common Mistake: Forgetting the comma after the previous project in the array. The last item should NOT have a comma after it.

Images look broken

Open the browser console (F12) and look for 404 errors. Make sure the filename in projects-data.js exactly matches the file in assets/images/ — including capitalization and extension.

Common Mistake: Using spaces or special characters in filenames. Stick to lowercase letters, numbers, and hyphens only.

Styles look wrong

Make sure css/style.css is linked in the <head> of your HTML file. If you renamed or moved the CSS file, update the <link> tag.

Contact form not working

The form uses Formsubmit. Make sure the action attribute in index.html points to your Formsubmit email URL, and that any required hidden fields are included.

Note: The first time you submit, Formsubmit sends a confirmation email. Click the link to activate the form.

Resume shows wrong projects

If a project appears twice on the resume, make sure the title is exactly the same in both projects-data.js and resume-data.js. The system uses the title to detect duplicates.

To fix it, open resume.html and use your browser's "Inspect Element" tool to check the rendered HTML.

Fonts not loading

Check your internet connection — Google Fonts are loaded from a CDN. If you need offline support, download the fonts and use a local @font-face declaration in your CSS.

Note: The site uses Inter for body text and Space Grotesk for headings in the docs page.
